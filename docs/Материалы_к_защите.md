## Этап 1. Текст для поля ответа

**Тема и назначение.** Модуль учёта движения канцелярских товаров. Он нужен кладовщику или офис-менеджеру: ведёт справочник канцтоваров, оформляет поступления от поставщиков и выдачу сотрудникам, сам считает остаток и предупреждает, что товар пора пополнить.

**Обязательные функции:**
- справочник товаров с поиском и архивом;
- поступление;
- выдача;
- автоматический расчёт остатка;
- история движения с фильтрами;
- контроль минимального количества;
- итоги за период;
- справочник сотрудников.

**Сущности и связи:**
- **Product:** артикул, наименование, единица измерения, минимальный остаток, признак архива.
- **Employee:** ФИО, отдел.
- **StockOperation:** товар, тип, количество, дата, сотрудник, поставщик или номер документа, комментарий.
- **Связи:** товар 1—N операции, сотрудник 1—N операции.

**Главное правило.** Остаток = Σ поступлений − Σ выдач. Выдать больше остатка нельзя. Если остаток ≤ минимума, товар помечается «Требует пополнения».

**Что работает.** Создан проект ASP.NET Core MVC на .NET 10 с моделью «Товар». Учебные записи хранятся в памяти и выводятся на странице /Products и по GET-запросу /api/products. Неизвестный Id возвращает 404.

**Ближайший шаг.** Перевести хранение на SQLite + EF Core и сделать CRUD.

**Коммит:** `Этап 1: каркас проекта, модель Товар, вывод списка на странице и через API`

## Этап 2. Текст для поля ответа

3. Изменить минимальный остаток.
4. Перезапустить приложение.
5. Убедиться, что товар на месте.

**Как готовится база.** При запуске выполняется `Database.Migrate()`. Другой вариант — команда `dotnet ef database update`.

## 20 вопросов к защите и ответы

1. **Что делает модуль?** Ведёт справочник канцтоваров, оформляет поступления и выдачи, сам считает остаток, показывает историю и предупреждает о пополнении.
2. **Главное правило?** Нельзя выдать больше, чем есть на складе. Остаток = сумма поступлений минус сумма выдач.
3. **Почему остаток не хранится в таблице?** Хранимое число может разойтись с операциями. Расчёт по истории всегда даёт правильный и проверяемый результат.
4. **Где проверяется, что товара хватает?** В методе `StockService.Issue`, перед сохранением выдачи.
5. **Что будет, если два человека одновременно выдадут один товар?** Проверка и запись выполняются внутри `lock`, поэтому вторая выдача увидит уже уменьшенный остаток.
6. **Почему операции нельзя удалять?** По ним считается остаток. Ошибку исправляют корректирующей операцией с комментарием, и история остаётся честной.
7. **Что такое MVC?** Model — данные, View — страница, Controller — принимает запрос и выбирает страницу. Так код разделён по задачам.
8. **Зачем слой Services?** Вся логика в одном месте, её можно тестировать без браузера, а контроллеры остаются простыми.
9. **Что такое EF Core?** Библиотека, которая связывает классы C# с таблицами базы. Запросы пишутся на LINQ, а EF Core переводит их в SQL.
10. **Что такое миграция?** Описание изменений структуры базы в коде. `Database.Migrate()` при запуске создаёт таблицы по миграциям.
11. **Почему SQLite?** База хранится в одном файле и не требует сервера: для одного кладовщика этого достаточно, а её легко скопировать и восстановить.
12. **Как вернуть учебные данные?** Остановить приложение, удалить `stationery.db` и запустить снова: DbSeeder заполнит базу.
13. **Как устроены тесты?** xUnit, база SQLite в памяти. Каждый тест получает новую пустую базу, вызывает метод сервиса и проверяет результат через Assert.
14. **Какие граничные случаи проверены?** Выдача ровно всего остатка разрешена, «остаток + 1» отклоняется, остаток, равный минимуму, означает «Требует пополнения», у нового товара остаток 0.
15. **Как проверено сохранение данных?** В тесте запись делается в одном DbContext, а чтение в новом. Вручную приложение перезапускалось, и данные остались на месте.
16. **Что такое OperationResult?** Объект-результат: Success, текст ошибки, предупреждение. Ошибки пользователя не бросают исключений, а показываются на странице.
17. **Что будет при открытии несуществующего товара?** Страница «Запись не найдена» с кодом 404, приложение не падает.
18. **Как работает поиск без учёта регистра по-русски?** Поиск выполняется в памяти через `Contains` с `StringComparison.OrdinalIgnoreCase`, потому что SQLite не умеет сравнивать кириллицу без учёта регистра.
19. **Зачем Git и GitHub Actions?** Git хранит историю этапов. GitHub Actions после каждого изменения собирает проект и запускает все тесты.
20. **Что можно улучшить?** Добавить роли и вход, учёт стоимости, автоматический заказ поставщику по товарам ниже минимума и выгрузку в Excel.

## «Объясни мне»: ключевые места кода

- `lock (IssueLock)` в StockService: внутри блока одновременно выполняется только одна выдача. Это защита от гонки при одновременных запросах.
- `StockCalculator.CalculateBalance`: `Where` отбирает поступления и выдачи, `Sum` складывает количества, результат — их разность.
- `IQueryable<StockOperation> query = …; if (filter.X != null) query = query.Where(…)`: запрос собирается по частям и выполняется в базе только при вызове `ToList()`.
- `OperationResult.Fail("…")`: вместо исключения возвращается объект с текстом ошибки. Контроллер добавляет его в ModelState, и форма показывает сообщение.
- `[ValidateAntiForgeryToken]`: защищает формы от отправки с чужого сайта.
- `modelBuilder.Entity<Product>().HasIndex(p => p.Article).IsUnique()`: уникальный индекс, при котором база сама не даст сохранить два одинаковых артикула.
- `TestDb`: открытое соединение SQLite `:memory:`. Пока оно открыто, база живёт, и разные DbContext видят одни и те же данные.
