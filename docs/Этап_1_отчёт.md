# Этап 1 — карта проекта и первый запуск

## 1. Что делаем и зачем
На этом этапе описываем, что именно должен уметь модуль, какие в нём данные и какое главное правило он соблюдает. Затем создаём каркас веб-приложения ASP.NET Core MVC (.NET 10) с первой сущностью «Товар». Данные пока хранятся в памяти, в статическом списке, чтобы сразу увидеть работающие страницы без базы данных. Результат этапа: проект запускается, показывает список товаров на странице и отдаёт его по GET-запросу `/api/products`, а сам проект лежит в Git.

**Назначение модуля.** Модуль автоматизирует учёт канцелярских товаров в организации: хранит справочник товаров, регистрирует поступления от поставщиков и выдачу сотрудникам. Пользователь модуля — кладовщик или офис-менеджер. Без автоматизации учёт ведётся в тетради или Excel, остаток считается вручную, из-за чего возникают ошибки и товар заканчивается неожиданно. Модуль сам считает текущий остаток по истории операций, не даёт выдать больше, чем есть на складе, и подсвечивает товары, которые нужно пополнить.

### Обязательные функции темы
1. Справочник товаров: добавление, просмотр, редактирование, архивирование, поиск по наименованию и артикулу.
2. Операция поступления товара (количество, дата, поставщик или номер документа).
3. Операция выдачи товара сотруднику (количество, дата, получатель).
4. Автоматический расчёт текущего остатка по формуле (остаток не вводится вручную).
5. Запрет выдачи сверх остатка.
6. История движения с фильтрами по товару, типу операции, сотруднику и периоду; карточка товара с его историей.
7. Контроль минимального количества: пометка «Требует пополнения», фильтр «Ниже минимума», предупреждение при выдаче.
8. Итоги за период: сколько поступило и сколько выдано.
9. Справочник сотрудников-получателей.

### Сущности, поля и связи

| Сущность | Поле | Тип | Описание / ограничение |
|---|---|---|---|
| **Product** (товар) | Id | int | первичный ключ |
| | Article | string | артикул, обязателен, уникален |
| | Name | string | наименование, обязательно |
| | Unit | string | шт., пачка, упаковка |
| | MinQuantity | int | минимальный остаток, ≥ 0 |
| | IsArchived | bool | товар в архиве (не удаляется) |
| **Employee** (сотрудник) | Id | int | первичный ключ |
| | FullName | string | ФИО, обязательно |
| | Department | string | отдел |
| **StockOperation** (операция) | Id | int | первичный ключ |
| | ProductId | int | внешний ключ → Product |
| | Type | enum | Поступление / Выдача |
| | Quantity | int | целое > 0 |
| | Date | DateTime | дата операции, не в будущем |
| | EmployeeId | int? | внешний ключ → Employee, обязателен для выдачи |
| | Supplier | string? | поставщик (для поступления) |
| | DocumentNumber | string? | номер документа (для поступления) |
| | Comment | string? | комментарий (в том числе для корректировок) |
| | CreatedAt | DateTime | когда запись создана в системе |

Связи: **Product 1 — N StockOperation**, **Employee 1 — N StockOperation** (только для выдач).

### Главное правило
Текущий остаток не хранится и не вводится руками, а вычисляется:

`Остаток = Σ(количество поступлений) − Σ(количество выдач)`

Выдача разрешена, только если `количество выдачи ≤ текущий остаток`. Если после операции `остаток ≤ MinQuantity`, товар получает пометку «Требует пополнения».

### Примеры неверных данных
1. Выдать 15 ручек при остатке 10 → «Недостаточно товара: на складе 10 шт.».
2. Количество 0 или −5 → «Количество должно быть целым числом больше 0».
3. Выдача без получателя → «Укажите сотрудника-получателя».
4. Поступление на архивный товар → «Нельзя проводить операции с архивным товаром».
5. Повторяющийся артикул KT-001 → «Товар с таким артикулом уже существует».
6. Дата операции завтрашним числом → «Дата операции не может быть в будущем».

## 8. Объясни мне

1. **`builder.Services.AddScoped<ProductService>();`** в `Program.cs` регистрирует сервис в «контейнере зависимостей». Когда ASP.NET создаёт контроллер, он видит в конструкторе параметр `ProductService` и сам подставляет объект. Контроллер не пишет `new`, поэтому сервис легко заменить: на этапе 2 он начнёт работать с базой, а контроллер останется прежним.

2. **`public static readonly List<Product> Products`** в `ProductStore`: `static` значит, что список один на всё приложение и живёт, пока приложение запущено. `readonly` запрещает подменить сам список, но добавлять в него элементы можно. После перезапуска список снова становится начальным, поэтому на этапе 2 нужна база данных.

3. **`[Display(Name = "Артикул")]`** — атрибут над свойством. Он задаёт русскую подпись поля, которую выводит `@Html.DisplayNameFor(...)`. `[Required]` и `[Range]` — правила проверки, они понадобятся в формах на этапе 2.

4. **`FirstOrDefault(p => p.Id == id)`** — метод LINQ «найди первый элемент, у которого Id равен id». Если такого нет, вернётся `null`, а не ошибка. Запись `p => p.Id == id` — лямбда-выражение, короткая функция-условие.

5. **`if (product == null) { Response.StatusCode = 404; return View("NotFound"); }`** — защита от неизвестного Id. Вместо падения пользователь видит понятную страницу, а браузер получает код 404 («не найдено»).

6. **`[ApiController]` и `[Route("api/products")]`**: первый атрибут говорит, что это API, которое отдаёт данные (JSON), а не HTML-страницы. Второй задаёт адрес. `[HttpGet("{id:int}")]` означает адрес `/api/products/5`, где `id` должен быть числом.

7. **`@model List<Product>` и `@foreach`** в представлении: первая строка сообщает странице, какие данные пришли из контроллера, а цикл выводит по строке таблицы на каждый товар. Символ `@` переключает с HTML на C#.

8. **`.gitignore`** перечисляет то, что Git не сохраняет: папки `bin` и `obj` (результат сборки, его можно получить заново), служебную папку IDE `.vs` и файл базы `*.db`.

## 9. Вопросы на защите

1. **Что такое MVC?** Это разделение программы на три части: Model (данные), View (страница) и Controller (принимает запрос, берёт данные и выбирает страницу). Так код проще читать и менять.
2. **Почему остаток не хранится в таблице товаров?** Если хранить его отдельно, он может разойтись с реальными операциями. Расчёт по формуле «поступления − выдачи» всегда даёт правильное число, и его можно проверить по истории.
3. **Зачем сервис, если контроллер мог бы сам взять список?** Логика собрана в одном месте и не зависит от страниц. Её можно протестировать отдельно, а при переходе на базу меняется только сервис.
4. **Что произойдёт, если открыть /Products/Details/999?** Сервис вернёт `null`, контроллер покажет страницу «Запись не найдена» с кодом 404. Приложение не упадёт.
5. **Почему данные пропадают после перезапуска?** На этом этапе они хранятся в оперативной памяти, в статическом списке. На следующем этапе их перенесём в базу SQLite, которая хранится в файле на диске.
