# Учёт движения канцелярских товаров

Курсовой проект по ПМ.01, МДК.01.01 «Разработка программных модулей».
Тема 19: «Проектирование и разработка модуля учета движения канцелярских товаров».
Выполнил: Санжаров Владислав Евгеньевич, группа ИСиП-23/1. Руководитель: Крючков Виталий Владимирович.

## Состав

| Каталог | Содержимое |
|---|---|
| `Stationery.Api/Domain` | классы предметной области: товар, подразделение, операция движения |
| `Stationery.Api/Data` | контекст EF Core, хранилища (репозитории), начальные данные `seed.json` |
| `Stationery.Api/Services` | бизнес-логика: справочники, поступление, выдача, остатки, история, отчёты |
| `Stationery.Api/Endpoints` | минимальный API: группы конечных точек |
| `Stationery.Api/wwwroot` | одностраничный интерфейс на HTML, CSS и JavaScript без сторонних библиотек |
| `Stationery.Tests` | 36 тестов MSTest: модульные и интеграционные (WebApplicationFactory) |
| `tools` | проверка API (`check_api.sh`) и сквозные сценарии в браузере (`e2e.mjs`, Playwright) |

## Запуск

Требуется .NET SDK 10.

```
dotnet run --project Stationery.Api
```

Адрес: http://localhost:5091. База `Stationery.Api/stationery.db` создаётся при первом запуске и заполняется
учебными данными; для восстановления учебных данных удалите файл базы. Тесты: `dotnet test`.

## Этап 4

- 36 тестов MSTest: сервисы с хранилищами в памяти и API целиком через `WebApplicationFactory` с отдельной базой.
- 25 сквозных сценариев в браузере (`docs/checks/results.json`, снимки экрана в `docs/checks/screens`).
- Дефекты, найденные при проверке кода этапа 3, и их исправление — `docs/defects.json`.
- Примеры запросов — `Stationery.Api/Stationery.Api.http`.

## Этап 3

- Операции движения: поступление (поставщик, накладная) и выдача подразделению (получатель); дата операции —
  не позже сегодняшней и не ранее чем за 30 дней.
- Остаток не хранится, а вычисляется запросом: сумма поступлений минус сумма выдач (`IMovementRepository.Balances`).
- Выдача больше остатка отклоняется (409); проверка остатка и запись выполняются в одной транзакции.
- История движения с отбором по периоду, виду операции, товару и подразделению; в карточке товара — остаток после каждой операции.
- Контроль минимального количества: ведомость остатков, список «К пополнению» с оформлением поступления на недостающее количество.
- Сводка по складу и отчёт о расходе по подразделениям за период.
- Товар с ненулевым остатком нельзя вывести из ассортимента.

## Этап 2

- Хранение в SQLite через Entity Framework Core; база `stationery.db` создаётся при запуске (`EnsureCreated`),
  начальные данные загружаются из `Stationery.Api/Data/seed.json` (19 товаров, 6 подразделений).
- Слой хранилищ (`Data/Repositories.cs`): сервисы обращаются к данным через интерфейсы `IProductRepository`, `IDepartmentRepository`.
- Справочник товаров: поиск, отбор по группе, добавление, изменение, вывод из ассортимента и возврат.
- Справочник подразделений: просмотр и добавление.
- Проверка данных атрибутами и фильтром конечной точки; ошибки в формате `{"message": "...", "errors": {...}}` на русском языке.

## Этап 1

- Решение `Stationery.sln`, веб-приложение `Stationery.Api` (ASP.NET Core, минимальный API, .NET 10).
- Интерфейс — одностраничное приложение на HTML, CSS и JavaScript без сторонних библиотек (`wwwroot`).
- Класс «Товар» (`Domain/Product.cs`); шесть товаров хранятся в памяти и выводятся на странице «Справочник товаров».
- API: `GET /api/products`, `GET /api/products/{id}` (для несуществующего кода — 404 с сообщением).
